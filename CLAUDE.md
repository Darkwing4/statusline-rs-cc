# statusline-rs

## Документация сегментов

Глобальный запрет на комментарии в коде здесь ослаблен ровно в одном файле: в `src/config_schema.rs` у каждой конфиг-структуры сегмента стоит один `///`-комментарий, и у каждого её поля — тоже один. Над структурой — одно предложение, ультра понятный питч: что сегмент показывает человеку, а не как он устроен. Над полем — одно предложение: что это значение меняет для человека, с единицами измерения прямо в тексте (секунды, KiB, символы). Не два предложения, не история реализации.

Эти строки и есть каталог сегментов: README их не перечисляет, а ссылается на `src/segments/` и `src/config_schema.rs`, и из тех же строк генерируется каталог для страницы редактора в `site/` — питч уходит на полку, подсказки полей в инспектор. Новый сегмент документируется строкой над структурой и строкой над каждым полем — README при этом не трогаем.

Остальной запрет в силе: никаких других `///`, `//!`, обычных `//`, `TODO` и `FIXME`.

## Имена сегментов

Имя варианта `SegmentSpec` должно само отвечать на вопрос «что я увижу на экране» — `MyLastPrompt`, а не `SessionTask`. Сегменты, которые дёргают внешнюю LLM, носят префикс `Llm`; `Agent` и `Subagent` зарезервированы за субагентами Claude Code.

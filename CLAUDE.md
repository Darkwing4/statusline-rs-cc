# statusline-rs

## Документация сегментов

Глобальный запрет на комментарии в коде здесь ослаблен ровно в одном месте: у каждой конфиг-структуры сегмента в `src/config_schema.rs` стоит один `///`-комментарий. Одно предложение, ультра понятный питч — что сегмент показывает человеку, а не как он устроен. Не два предложения, не перечисление полей, не история реализации.

Этот питч и есть каталог сегментов: README их не перечисляет, а ссылается на `src/segments/` и `src/config_schema.rs`, и из тех же строк генерируется каталог для страницы редактора в `site/`. Новый сегмент документируется одной строкой над структурой — README при этом не трогаем.

Остальной запрет в силе: никаких других `///`, `//!`, обычных `//`, `TODO` и `FIXME`.

## Имена сегментов

Имя варианта `SegmentSpec` должно само отвечать на вопрос «что я увижу на экране» — `MyLastPrompt`, а не `SessionTask`. Сегменты, которые дёргают внешнюю LLM, носят префикс `Llm`; `Agent` и `Subagent` зарезервированы за субагентами Claude Code.
